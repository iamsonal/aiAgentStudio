## What Pluto does

An agent reads records, calls the tools you give it, and writes an answer. It runs as Apex in your org. Your data stays in Salesforce except for what the agent sends to the model.

<CardGrid>
  <Card title="Standard licenses" icon="star">
    Pluto runs on the Salesforce licenses your users already have. It needs no paid AI add-on and no extra per-conversation fee. You pay your model provider for the tokens you use.
  </Card>
  <Card title="Any model provider" icon="random">
    Connect OpenAI, Azure OpenAI, or any endpoint that serves the OpenAI Responses API. For another provider, a developer writes one Apex class.
  </Card>
  <Card title="Approvals before actions" icon="approve-check">
    Make a person approve a tool call before it runs. Send it to a user, a queue, the record owner, or the requester's manager. A policy can ask only for large refunds and let small ones through. The agent never approves its own work.
  </Card>
  <Card title="A record of every step" icon="magnifier">
    Each run stores every model call, tool call, approval, and decision. The run story in Pluto Console shows who started it, what the agent saw, what it did, and who approved it.
  </Card>
  <Card title="Runs that recover" icon="setting">
    A schedule checks every 10 minutes for runs that stopped and continues them. A tool call that changed an outside system is never repeated blindly. An admin can rescue or cancel any run without code.
  </Card>
  <Card title="Sensitive data stays out of the model" icon="warning">
    Emails, phone numbers, card numbers, US SSNs, IBANs, and classified fields become tokens before the model sees them. Only tools you allow get the real values back.
  </Card>
  <Card title="Tools without code" icon="puzzle">
    Give an agent tools to query records with your own SOQL, create or update records with fields you allow, post to Chatter, or run a Flow. Developers add Apex tools through a published contract.
  </Card>
  <Card title="Spending limits per run" icon="list-format">
    Each agent caps model calls, tool calls, and tokens per run. Set token prices on the model, and each call records its estimated cost.
  </Card>
</CardGrid>

## Why Pluto

1. You keep your current licenses. An agent runs as Apex in your org, with no AI add-on to buy.
2. You choose the model and can change it later. Agents point to an Agent Model record. Switching providers changes that record, not the agents.
3. You can explain every result. When someone asks why the agent changed a record, the run story answers with the model call, the tool call, and the approval behind it.
4. Admins build with records and Flows. An agent is an Agent Definition with tools attached. You start it from a Flow action, so record-triggered, scheduled, and screen Flows all work.
5. You can read and change the source. Pluto is free under the AGPL. Your own tools, model providers, and policies can stay private.

## What you can build

| Use an agent to | For example |
| --- | --- |
| Sort or summarize work as it arrives | Triage each new Case: set its Priority and post a short note to its Chatter feed. |
| Draft text a person checks before it goes out | Draft a reply to a customer for the case owner to review. |
| Change records only after someone agrees | Update an Opportunity stage only after the account owner approves. |
| Work through many records without a person | Review every open Case each night and flag the ones that need attention. |
| Help a user on a record page | A screen Flow on the Case page where the user asks questions over several messages. |
| Wait for a slow outside system | Start a credit check, wait hours for the answer, then continue the run. |
